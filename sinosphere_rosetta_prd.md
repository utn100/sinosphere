# 1. Executive Summary & Vision

### 1.1 Overview
**Sinosphere Rosetta** is a specialized, information-dense mobile dictionary, text parser, and interactive component graph explorer tailored specifically for Vietnamese-English bilingual learners of East Asian languages (Mandarin Chinese & Sino-Korean).

Unlike conventional language learning apps that emphasize gamification, streak mechanics, or artificial mnemonics, Sinosphere Rosetta bridges **etymological component logic (Chiết tự)**, **Hán-Việt semantic anchoring**, and **English analytical precision** into a cohesive, offline-first mobile experience — augmented by AI for coverage beyond the curated database.

### 1.2 Core Vision
To unlock the "Sinosphere Code" for bilingual learners by visualizing Chinese and Sino-Korean characters not as isolated symbols to be memorized by rote, but as an interconnected network of structural radicals (*bộ thủ*), phonetic roots, and shared East Asian semantic evolution — with a personal graph that grows as the learner reads and discovers new words.

# 2. User Persona & Problem Statement

### 2.1 Target Persona
- **Language Background:** Native/fluent in Vietnamese, fluent/proficient in English, actively learning Mandarin Chinese (HSK 1–9) and/or Korean (TOPIK 1–6)
- **Workflow Preference:** Prefers modern, sleek English user interfaces, but relies heavily on Hán-Việt cognates as an immediate, high-bandwidth semantic bridge to Chinese and Korean vocabulary

### 2.2 Core Pain Points
1. **The Hán-Việt Disconnect:** Western Chinese/Korean dictionary apps either relegate Hán-Việt readings to deeply buried sub-menus or ignore them completely
2. **Outdated Local Apps:** Existing Vietnamese-developed Hán-Việt dictionaries feature obsolete UIs, lack interactive radical breakdown, and lack integration with modern English dictionary databases
3. **Isolated Memory Silos:** Standard vocabulary apps treat characters as discrete items rather than nodes in a shared structural network, missing the opportunity to leverage component reuse (*bộ thủ*)
4. **DB Coverage Gaps:** No offline dictionary covers 100% of real-world text — song lyrics, news articles, and social media use vocabulary outside any fixed wordlist

## Feature 1: Unified Character Card (P0)

- **Single-Screen Hierarchy:** Displays the character, Pinyin/Hangul, Hán-Việt reading (formatted prominently in bold uppercase as the semantic anchor), HSK level, stroke count, and precise English definitions in a single view
- **Cross-Linguistic Cognates:** Displays Japanese Onyomi, Korean Hanja equivalents, and stroke count
- **Structural Tree Breakdown:** Interactive component list separating components by functional role:
  - *Semantic Components (Biểu ý)* — emerald colour coding
  - *Phonetic Components (Biểu âm)* — blue colour coding
  - *Iconic/Pictographic Elements (Tượng hình)* — purple colour coding
- **AI-Generated Chiết Tự Narrative:** A short Vietnamese-language mnemonic story explaining how sub-components combine logically. Generated by AI on first request and cached locally — never re-fetched for the same character
- **Frequent Compounds:** List of common compound words using this character, each showing Pinyin, Hán-Việt, and English. Tap to open the word bottom sheet
- **Bookmark:** Save to personal collections
- **Graph Preview Teaser:** Button at the bottom of the card linking directly to the 3-tier graph scoped to this character's primary radical

## Feature 2: 3-Tier Interactive Node Graph Explorer (P0)

### Graph Topology
Forces nodes into a strict 3-tier hierarchy:
1. **Tier 1 (Root Component):** Radical / Sub-component (e.g. `土` Earth/Thổ, `日` Sun/Nhật, `心` Heart/Tâm) — rendered as amber filled nodes
2. **Tier 2 (Single Character):** Individual characters derived from the root — rendered as emerald filled nodes
3. **Tier 3 (Compound Word):** Multi-character vocabulary using Tier 2 characters — rendered as sky-bordered dark nodes

### Resonance-Aware Visual Weight
In "All words" mode, Tier 3 nodes are visually weighted by `hanviet_resonance`:
- `high` — bright sky-blue with amber dot marker
- `medium` — indigo-tinted, reduced opacity
- `low` — muted slate, near-ghosted

### Filter Toggle (3 modes)
- **All words** — full seeded + user graph, resonance-weighted visuals
- **Strong cognates** — only `hanviet_resonance = high` compounds; strips low-value nodes so the graph shows the highest-leverage vocabulary skeleton
- **My words** — only user-added learned nodes (violet dashed style); shows friendly empty state if none added yet

### Gesture & Touch Controls
- Pinch-to-zoom and pan across the canvas
- Tap Tier 1 node — highlights all child characters
- Tap Tier 2 node — expands/collapses Tier 3 compounds with visual edge highlighting
- Tap any node — updates floating inspector bar (symbol, pinyin, hán-việt, type, definition)

### Radical Picker
- Grid of common radicals for switching the active graph
- Full 214 Kangxi radical index in final release
- "Explore Component Graph" on Dict Card navigates directly to the graph scoped to the current character's primary radical

### User-Grown Graph
- `+ Add word` button opens a form with Chinese, Pinyin, Hán-Việt, English fields
- As user types the Chinese field, the app detects the best radical bucket and shows a hint: *"Will be added as a compound node under 日 · NHẬT"*
- Single character → Tier 2 node; multi-character word → Tier 3 node under the best matching parent
- User-added nodes render with violet dashed border + ✦ badge, distinct from seeded nodes
- All user additions persisted to local SQLite and survive app restarts

## Feature 3: Smart Reader & Lyrics Parser (P0)

### Text Processing Pipeline
1. **Segmentation** — Jieba C++ tokenizer (offline, via FFI) splits raw Chinese text into word tokens
2. **DB Lookup** — each token is looked up in SQLite for pinyin, hán-việt, definition, and `hanviet_resonance`
3. **AI Fallback** — tokens not found in the DB are sent to the AI Dictionary Fallback (see Feature 5). Result is cached locally; the annotation is always complete, never patchy
4. **Interlinear Render** — Hán-Việt readings (or Pinyin, toggle-switchable) displayed above each word using ruby annotation

### Annotation Mode Toggle
- **HV mode** — Hán-Việt readings above each word; amber colour, uppercase
- **PY mode** — Pinyin above each word; sky colour

### Tap-to-Lookup Bottom Sheet
Tapping any annotated word opens a bottom sheet without losing scroll position:
- Character, Hán-Việt, Pinyin, English definition
- Quick per-character component pills (tap to open full Dict Card)
- Graph status indicator: "Already in your graph" (green) or "+ Add to Graph" (enabled)
- **4 action buttons (always visible, sticky footer):**
  - Full Card — navigate to Dict Card for first character
  - + Add to Graph — adds the word to the user graph, pre-filled from annotation data
  - Bookmark — saves to bookmarks
  - Save to Deck — assigns to an existing or new custom collection

### Vocabulary Harvest Panel
Appears automatically below the reading area after any annotation:
- Deduplicated list of all unique words found in the text
- **3 filter tabs:** All / Strong HV cognates / New to graph
- Each word shows: resonance dot, character, Hán-Việt, English, "In graph" badge or "+ Graph" button
- Star individual words; bulk-add all starred words to the graph in one tap ("Add starred → Graph")

### Reading History
- Every annotated text is auto-saved to local SQLite with title, date, token list
- Accessible via History button → full-screen overlay with list of past texts
- Each history item shows: title, date, word count, HV cognate count
- Tap to reload the full annotated view and harvest panel
- Individual delete or clear all

### Seeded Snippet Library
10–15 curated texts (popular songs, news excerpts, literature) pre-loaded at install — gives users immediate content to explore before pasting their own

### AI-Enhanced Annotations (Phase 3 addition)
Beyond DB lookup, AI provides:
- **Sentence-level grammar notes** — explains particles (的, 了, 把) in context of the specific sentence, not a generic definition
- **Register detection** — flags formal, colloquial, literary, or internet slang usage
- **Hán-Việt confidence notes** — for words where Vietnamese cognate has semantically drifted (e.g. 城市 → colloquial "thành phố" vs formal THÀNH THỊ)

## Feature 5: AI Dictionary Fallback & Intelligence Layer (P0 for Reader, P1 for standalone)

### AI Dictionary Fallback
When a word is not found in the local DB (triggered by Reader segmentation or manual search):
- Call LLM (Claude Haiku) with a structured prompt requesting: pinyin, hán-việt reading, hanviet_resonance estimate, english definition, radical placement, Chiết Tự breakdown
- Response returned as structured JSON via tool use
- Cached to local SQLite immediately — never re-fetched for the same word
- Offline graceful degradation: if no network, show `···` with a "Look up when online" badge

### AI Chiết Tự Story Generator
- For any character lacking a hand-written etymology narrative, generate a short Vietnamese-language mnemonic story on first view
- Prompt is constrained to the character's known semantic + phonetic components from the DB
- Cached locally after first generation
- Indistinguishable from curated content in the UI — no "AI generated" badge needed given the structured prompt

### Text Difficulty Scorer
Before annotating a pasted text, AI analyzes and returns:
- Estimated HSK level of the passage
- % of words with high Hán-Việt resonance
- Top 5 unknown words to focus on
- Displayed as a summary banner before annotation renders

### Personalized Graph Suggestions (P2)
After a user accumulates reading history and saved words:
- Analyze radical patterns and suggest related high-resonance words not yet in the user's graph
- Example: *"You've saved 8 words with 心 radical — here are 5 more high-resonance words you're likely to encounter"*
- Runs as a periodic background task, results cached locally

### Conversational Chiết Tự Explainer (P2)
A scoped chat interface (not a general chatbot) where users can ask questions anchored to the Sinosphere / Hán-Việt domain:
- *"Why does 明 mean bright?"*
- *"What's the difference between 情 and 感 in compounds?"*
- *"Which radical should I learn first for reading news?"*
- Model has the local DB as context; answers stay anchored to the app's framing

---

## Feature 6: Sino-Korean Hanja Expansion Engine (P2)

- **Syllable-to-Hanja-to-Hán-Việt Mapping:** Parse Korean vocabulary via Hanja roots (e.g. `학교 (Hak-gyo)` → `學 (Học) + 校 (Hiệu)` → `HỌC HIỆU` → School)
- **Etymological Word Tagging:** Automatically tag Korean entries as `Sino-Korean (한자어)` or `Native Korean (순우리말)`
- **Korean Graph Integration:** Expand Tier 1/2/3 nodes to map shared Hanja roots to native Hangul syllables
- **Cross-Language Comparative Mode:** Side-by-side comparison of Chinese compounds alongside Sino-Korean counterparts (e.g. Chinese `城市` vs Korean `都市 (도시)`)
- **Korean Reader:** MeCab-ko tokenizer integration for Korean text segmentation

# 5. Data Architecture

## 5.1 Word Selection Policy

| Source | Count | Criteria |
| :--- | :--- | :--- |
| HSK 1–9 | ~11,000 | Non-negotiable backbone |
| High Hán-Việt Cognates (non-HSK) | ~3,000–5,000 | `hanviet_resonance = high`, living in modern Vietnamese |
| High-frequency non-HSK | ~2,000–3,000 | Subtitles/news corpora, colloquial usage |
| AI-generated (user cache) | Unbounded | Per-user, cached locally on first lookup |
| **Total seeded** | **~16,000–19,000** | |

**Exclusions:** Highly literary Classical Chinese with no living Vietnamese cognate; technical jargon without HV resonance; proper nouns; HSK words that are purely grammatical particles with no semantic content.

## 5.2 `hanviet_resonance` Field

| Value | Meaning |
| :--- | :--- |
| `high` | Reading is identical or near-identical to modern Vietnamese; meaning preserved. User recognises instantly |
| `medium` | Reading exists but meaning has drifted, or it's formal/literary register (known passively) |
| `low` | Hán-Việt reading exists but is archaic, rarely used in spoken Vietnamese |
| `none` | Native Chinese compound with no meaningful Sino-Vietnamese equivalent |

## 5.3 Relational Schema (SQLite)

```sql
CREATE TABLE components (
    id TEXT PRIMARY KEY,
    symbol TEXT NOT NULL,
    pinyin TEXT NOT NULL,
    han_viet TEXT NOT NULL,
    english_def TEXT NOT NULL,
    stroke_count INTEGER NOT NULL
);

CREATE TABLE characters (
    id TEXT PRIMARY KEY,
    symbol TEXT NOT NULL,
    pinyin TEXT NOT NULL,
    hangul TEXT,
    han_viet TEXT NOT NULL,
    english_def TEXT NOT NULL,
    etymology_story TEXT,        -- hand-written or AI-generated, cached
    hsk_level INTEGER,
    jp_onyomi TEXT,
    stroke_count INTEGER
);

CREATE TABLE character_components (
    character_id TEXT NOT NULL,
    component_id TEXT NOT NULL,
    component_type TEXT CHECK(component_type IN ('semantic', 'phonetic', 'iconic')),
    PRIMARY KEY (character_id, component_id),
    FOREIGN KEY (character_id) REFERENCES characters(id),
    FOREIGN KEY (component_id) REFERENCES components(id)
);

CREATE TABLE compound_words (
    id TEXT PRIMARY KEY,
    simplified TEXT NOT NULL,
    traditional TEXT,
    pinyin TEXT NOT NULL,
    hangul TEXT,
    han_viet TEXT NOT NULL,
    han_viet_resonance TEXT DEFAULT 'medium'
        CHECK(han_viet_resonance IN ('high', 'medium', 'low', 'none')),
    vietnamese_note TEXT,        -- colloquial VN equivalent where meaning has drifted
    english_def TEXT NOT NULL,
    hsk_level INTEGER,           -- NULL if non-HSK
    frequency_rank INTEGER,      -- corpus rank; lower = more common
    origin_type TEXT DEFAULT 'sino_chinese'
        CHECK(origin_type IN ('sino_chinese', 'sino_korean', 'native_korean')),
    is_cognate_anchor INTEGER DEFAULT 0,  -- manually curated high-value teaching words
    ai_generated INTEGER DEFAULT 0        -- 1 if sourced from AI fallback cache
);

CREATE TABLE word_characters (
    word_id TEXT NOT NULL,
    character_id TEXT NOT NULL,
    position INTEGER NOT NULL,
    PRIMARY KEY (word_id, character_id, position),
    FOREIGN KEY (word_id) REFERENCES compound_words(id),
    FOREIGN KEY (character_id) REFERENCES characters(id)
);

CREATE TABLE user_collections (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    icon TEXT,
    created_at INTEGER NOT NULL
);

CREATE TABLE user_collection_words (
    collection_id TEXT NOT NULL,
    word_id TEXT NOT NULL,
    added_at INTEGER NOT NULL,
    PRIMARY KEY (collection_id, word_id)
);

CREATE TABLE reading_history (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    raw_text TEXT NOT NULL,
    token_json TEXT NOT NULL,    -- serialized token array with annotations
    created_at INTEGER NOT NULL
);

CREATE TABLE ai_cache (
    query TEXT PRIMARY KEY,      -- the Chinese word/character queried
    response_json TEXT NOT NULL, -- full structured AI response
    cached_at INTEGER NOT NULL
);
```

# 8. Non-Functional Requirements

1. **Search latency:** Dictionary queries must complete in under **50ms** (SQLite indexed on simplified, pinyin, han_viet, english)
2. **Graph performance:** Node interactions and animations must maintain **60fps** for up to 150 simultaneously rendered nodes
3. **AI fallback latency:** First-time AI lookup must return in under **3 seconds** on a standard mobile connection; subsequent lookups are instant (cached)
4. **Offline capability:** All core features (search, graph, reader with DB words, saved decks) function 100% offline. AI features degrade gracefully — show cached results or a "look up when online" indicator
5. **DB size:** Seeded SQLite database must stay under **150MB** installed
6. **RAM:** Peak usage must remain under **200MB** during graph animation
7. **Accessibility:** Full support for system Light and Dark themes; dynamic font scaling for CJK strokes and Hangul typography

# 9. Development Roadmap

- **Gate:** DB file under 150MB, all 19,000 seeded words have pinyin + hán-việt + english + resonance score
